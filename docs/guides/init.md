# Starting from your setup

`hlock init` writes a `harness.toml` from what you already use, so you don't start from a
blank file. It scans your agent harness and your project, shows what it found, and lets you
choose what goes in.

```console
$ hlock init
scanning claude-code  (running inside it)

Target harness  the harness this lock is for
1  ●  Claude Code  2.1.285 · running inside it
  pick a number, Enter keeps ●:
LLM candidates  models resolve may try for the planner role
1  ✓  anthropic:opus                       Claude Code default model
2  ·  ollama:qwen3:8b                      Ollama · on disk, fits 16 GB
3  ·  ollama:gpt-oss:20b                   Ollama · not downloaded, fits 16 GB
…
6  ·  anthropic:claude-opus-5-5            ANTHROPIC_API_KEY is set
  toggle numbers (1 3 5-7), a = all, n = none, Enter = done: 2
…
MCP servers  recorded in [tools]
1  ✓  github  Claude Code (user) · npm:@modelcontextprotocol/server-github
…
✓ wrote harness.toml  (2 models, 1 harness, 2 decision models, 1 MCP server, 2 skills, 1 instruction file, 1 task pack)
! the project uses pydantic-ai; choose "Your own agent" to add a [harnesses] stub for it
next → review harness.toml  ·  hlock resolve
```

Everything your harness uses today starts checked (`✓`). Toggle items by number (`1 3`,
ranges like `5-7`), `a` for all, `n` for none, and press Enter to move on.

## What it scans

| Where | What becomes a choice |
|---|---|
| Your target harness | Its default and small models, the models configured under its providers (including self-hosted servers on your network), MCP servers, skills, and user-level instruction files. Uses the same capture as [`hlock pin`](pin.md). |
| Local runtimes | Models on disk and catalog models that fit your memory, for each installed runtime (Ollama, LM Studio, …) |
| Your environment | API providers whose keys are set (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `OPENROUTER_API_KEY`, …). Keys are checked by name; their values are never read into the file. |
| Other harnesses | Every installed agent CLI, as a harness candidate |
| The project | Skills in `skills/`, `.agents/skills/`, `.claude/skills/` and the like; `AGENTS.md`, `CLAUDE.md` and other instruction files; task packs (any directory with a `pack.toml`); agent frameworks in `pyproject.toml` (pydantic-ai, deepagents, langgraph, …) |

The target harness is chosen as in [Harnesses](harnesses.md#target-a-harness): `--harness`,
the harness you're running inside, or the only one installed. Skills a harness manages itself
(built-in, from plugins, or synced from an account) aren't listed.

## What it writes

```toml title="harness.toml"
# hlock manifest, generated by `hlock init` from your Claude Code setup.
# `hlock resolve` searches [candidates]. [tools], [skills] and [instructions] are
# recorded in the lock but not searched yet. Comments say where each entry came from.

[project]
name = "triage"

[target]
harness = "claude-code"  # 2.1.285 · running inside it

[tasks]
packs = ["./tasks"]
seeds = 2

[candidates.llm.planner]
any_of = [
  "anthropic:opus",  # Claude Code default model
  "ollama:qwen3:8b",  # Ollama · on disk, fits 16 GB
]

[candidates]
decision = ["none", "rules:default"]
harness = ["claude-code"]

[tools]  # MCP servers; secrets are listed by name, never stored here
github = { mcp = "npm:@modelcontextprotocol/server-github", env = ["GITHUB_TOKEN"] }

[skills]
release-notes = { path = "./skills/release-notes", editable = true }
mine = { path = "~/.claude/skills/mine" }

[instructions]
files = ["AGENTS.md"]
…
```

Only `[candidates]` (models, harnesses, decision models) changes what `hlock resolve`
searches today. `[tools]`, `[skills]` and `[instructions]` are recorded in the lock but not
searched yet. Choosing **Your own agent** adds a commented
[`[harnesses.<id>]`](harnesses.md#your-own-agent-frameworks-and-custom-scripts) stub for you
to fill in with an entrypoint. If no task pack is found, `init` leaves a placeholder and says
so; `hlock resolve` needs one.

## Options

```bash
hlock init                      # on a terminal: scan, then ask
hlock init --yes                # take the suggestions without asking (scripts, agents)
hlock init --dry-run            # print the manifest instead of writing it
hlock init --json               # print what the scan found, as JSON
hlock init --dir ~/work/agent   # scan and write into another directory
hlock init --harness pi         # scan a specific harness
hlock init --template           # the minimal offline starter, no scanning
```

When stdin isn't a terminal, `init` takes the suggestions as `--yes` does. It writes
`harness.toml` in the current directory (or `--dir`, or `-m PATH`), never over a parent
project's manifest. It refuses to overwrite an existing file unless you pass `--force`.
